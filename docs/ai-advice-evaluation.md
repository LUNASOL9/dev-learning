- 제공된 결과는 모두 category와 checks 두 항목을 갖췄다. 전체 시도의 오류율까지 측정한 것은 아니다.

- "프린터 드라이어" 오기와 성능 저하를 "API 성능 향상"으로 분류한 의미 오류가 있었다.

- 같은 입력에도 점검 초점과 구체성이 달라졌다.

이 표본에서는 지침과 예시 추가가 구체적인 행동 안내를 안정적으로 개선했다고 보기 어렵다. 입력 보강으로 일부 관련성은 개선됐으나 잘못된 분류와 막연한 안내가 남았다. 작은 수동 표본이므로 모델의 한계나 추론 효과를 확정하지 않는다. 프롬프트 확장을 멈추고 조건을 고정해 후속 비교를 진행한다.

1. 분류가 입력의 의미와 모순되지 않아야 한다. 성능 저하를 향상으로 표시하지 않는다.
2. 두 확인 사항 모두 확인 대상과 실행할 행동을 포함한다. 가능한 경우 확인 위치나 비교할 값·현상을 명시한다.
3. 정보가 부족하면 지연 구간·연결 방식 등을 좁히는 점검을 우선한다. 제공되지 않은 원인을 확정하지 않는다.
4. 로그·현재 상태·측정을 먼저 제안한다. 근거 없는 업데이트·재설치·설정 변경을 권하지 않는다.
5. 기술 용어를 정확히 사용하고 두 항목이 중복되지 않도록 한다.

후속 평가에서는 응답별로 각 목표를 충족/부분 충족/미충족으로 기록하고 근거 문구를 남긴다. 속도와 품질은 별도로 기록하며 빠르다는 이유로 의미 오류를 통과시키지 않는다.
